# 数据湖治理配置中心

离线版数据湖治理配置工具，涵盖多源接入通道、分层表结构设计、湖区分区策略、流批转换编排、元数据编目检索与资源计量管理，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/governance-engine.ts 治理规则冲突裁决：优先级、处置、命中台账
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `lake-govern-config:entries` 这一项，或调用 `resetModule(模块)`。

## 湖仓治理冲突裁决

多条治理规则命中同一「治理对象」时，`src/api/governance-engine.ts` 会做一次裁决，每个对象只留下
一个有效处置结果；其余命中保留在命中台账里可追溯，但不再重复改变对象。

优先级按字典序比较，越靠前越优先：

1. **影响范围**：全湖级 > 业务域级 > 分区级 > 表级 > 字段级；
2. **触发阈值**：同一影响范围下，数值越小越严格；
3. **当前生效状态**：已启用 > 待校验 > 草稿 > 已停用。

只有「已启用」的规则能真正改变对象，其他状态只记为未生效命中。三项都相同时按规则编号升序，
保证同一冲突每次裁决结果一致。

相关语义：

- **旧处置按上线时规则保留**：处置里冻结胜出规则当时的快照。规则后续被修改或新增，已存在的处置
  不会回写，只有下一次触发才按新优先级重新裁决（看板会标注「按上线时旧规则保留」）。
- **相同冲突只算一次**：对象 + 规则关键字段 + 胜出者构成冲突指纹，指纹相同视为重复到达，
  不写盘、不改变处置。
- **并发只执行一次**：同一对象的并发触发合并成一次裁决。
- **跨模块告警只留最高优先级结论**：质量监控按对象只保留一条治理告警，较弱结论不覆盖更强旧告警。
- **写入失败保持旧处置**：业务清单与裁决状态存在同一个 localStorage 文档里、同一次写入，
  写入失败时内存与存储都保持旧状态，不会出现「规则清单已变但质量告警没落」的半套状态。
- 治理页的「重置治理数据」会同时重置治理规则与裁决状态。
